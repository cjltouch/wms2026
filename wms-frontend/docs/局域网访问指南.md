# WMS 局域网访问配置指南

把本机（Mac）上的 WMS 前后端服务开放给同一局域网内的其他人访问。

> 当前本机局域网 IP：**172.20.10.6**（en0）。IP 会随网络变化，下面有自动获取命令。

---

## 一、访问地址

别人在浏览器打开（与你在同一 WiFi/局域网下）：

| 服务 | 地址 |
|------|------|
| 前端页面（推荐） | `http://172.20.10.6:3001` |
| 后端接口（直连，一般不用） | `http://172.20.10.6:8081` |

前端已配置代理：所有 `/wms-api/**` 请求会自动转发到后端 `127.0.0.1:8081`，所以别人只需访问 **前端 3001 端口**，登录后即可正常使用，无需关心后端地址。

---

## 二、一次性配置（已完成，仅记录）

### 1. 前端：让 Vite 监听所有网卡

文件：`vite.config.ts`

```ts
server: {
  host: true,                  // 监听所有网卡，局域网可通过本机 IP 访问
  allowedHosts: true,           // 允许所有主机名（含 Cloudflare Tunnel 公网域名）
  port: 3001,
  proxy: {
    '/wms-api': {
      target: 'http://127.0.0.1:8081',
      changeOrigin: true
    }
  }
}
```

> 关键是 `host: true`。不加它 Vite 默认只绑 `localhost`，局域网访问不到。
>
> `allowedHosts: true` 用于放行 Cloudflare Tunnel 的 `xxx.trycloudflare.com` 域名。Vite 5.4+ 会强制校验主机名，否则公网访问会返回 403。详见 `docs/Cloudflare-Tunnel配置指南.md`。

### 2. 后端：Spring Boot 默认绑 0.0.0.0

后端无需额外配置，Spring Boot 默认监听所有网卡。只要 `server.port=8081` 启动，局域网就能访问 8081。

### 3. 防火墙：保持关闭或放行 node/java

```bash
# 查看防火墙状态
sudo /usr/libexec/ApplicationFirewall/socketfilterfw --getglobalstate

# 若防火墙开启，放行 node（前端）和 java（后端）
sudo /usr/libexec/ApplicationFirewall/socketfilterfw --add $(which node)
sudo /usr/libexec/ApplicationFirewall/socketfilterfw --unblockapp $(which node)
sudo /usr/libexec/ApplicationFirewall/socketfilterfw --add $(java -version 2>&1 | head -1 >/dev/null; which java)
sudo /usr/libexec/ApplicationFirewall/socketfilterfw --unblockapp $(which java)

# 或直接关闭防火墙（内网开发可接受）
sudo /usr/libexec/ApplicationFirewall/socketfilterfw --setglobalstate off
```

## 三、启动服务（每次开机后执行）

### 方式 A：一键启动脚本

把下面保存为 `scripts/start-lan.sh`（项目已提供），赋权后执行：

```bash
#!/usr/bin/env bash
set -e

FE_DIR="$HOME/Documents/trae_projects/wms-frontend"
BE_DIR="$HOME/Documents/trae_projects/wms-backend"

echo "=== 获取局域网 IP ==="
LAN_IP=$(ipconfig getifaddr en0 2>/dev/null || ipconfig getifaddr en1 2>/dev/null)
echo "局域网 IP: $LAN_IP"

# 清掉可能残留的旧进程
for port in 3001 8081; do
  pids=$(lsof -ti:$port 2>/dev/null)
  [ -n "$pids" ] && kill -9 $pids 2>/dev/null && echo "已清理 $port 端口旧进程"
done
sleep 2

echo "=== 启动后端 8081 ==="
cd "$BE_DIR"
xattr -rc target/ 2>/dev/null || true
LOG_BASE=/tmp/wms-backend-logs nohup mvn spring-boot:run > /tmp/wms-backend.log 2>&1 &
echo "后端 PID: $!  日志: /tmp/wms-backend.log"

echo "=== 启动前端 3001 ==="
cd "$FE_DIR"
nohup npm run dev > /tmp/wms-frontend.log 2>&1 &
echo "前端 PID: $!  日志: /tmp/wms-frontend.log"

echo "=== 等待服务就绪 ==="
for i in $(seq 1 60); do
  be=$(curl -s -o /dev/null -w "%{http_code}" http://127.0.0.1:8081/wms-api/api/system/auth/captcha 2>/dev/null)
  fe=$(curl -s -o /dev/null -w "%{http_code}" http://127.0.0.1:3001/ 2>/dev/null)
  [ "$be" = "200" ] && [ "$fe" = "200" ] && break
  sleep 2
done

echo ""
echo "================ 就绪 ================"
echo "前端:  http://$LAN_IP:3001"
echo "后端:  http://$LAN_IP:8081"
echo "======================================="
```

使用：

```bash
chmod +x scripts/start-lan.sh
./scripts/start-lan.sh
```

### 方式 B：手动分两个终端

## 四、常用排查命令

```bash
# 1. 查看本机局域网 IP（en0=WiFi，en1=有线）
ipconfig getifaddr en0
ifconfig | grep "inet " | grep -v 127.0.0.1

# 2. 查看端口监听（应为 *:3001 / *:8081，而非 127.0.0.1 或 [::1]）
lsof -nP -iTCP:3001 -sTCP:LISTEN
lsof -nP -iTCP:8081 -sTCP:LISTEN

# 3. 本机自测（通则配置没问题，不通先查本机）
curl -I http://172.20.10.6:3001/
curl -I http://172.20.10.6:8081/wms-api/api/system/auth/captcha
curl -I http://172.20.10.6:3001/wms-api/api/system/auth/captcha   # 前端代理后端

# 4. 别人电脑上 ping 不通？查防火墙
sudo /usr/libexec/ApplicationFirewall/socketfilterfw --getglobalstate
# 状态 = 1 表示防火墙开启，执行：sudo ... --setglobalstate off

# 5. 别人能 ping 通 IP 但打不开页面？查端口是否绑 0.0.0.0
#    若显示 127.0.0.1:3001 说明没加 host:true，检查 vite.config.ts

# 6. 查看服务日志
tail -f /tmp/wms-frontend.log
tail -f /tmp/wms-backend.log

# 7. 停止服务
lsof -ti:3001,8081 | xargs kill -9
```

## 五、别人访问不到的排查清单

### 5.0 快速定位（按现象分流）

| 现象 | 含义 | 直接跳到 |
|------|------|---------|
| ping 不通 IP | 网络层不通（不同网段/AP 隔离/防火墙 stealth） | 5.1、5.5、5.6 |
| **能 ping 通但浏览器打不开** | **几乎肯定是本机防火墙拦了入站 TCP** | **5.4** |
| 浏览器返回 403 `Blocked request` | Vite `allowedHosts` 没放行域名 | 5.7 |
| 浏览器返回 502 / 504 / 连接重置 | Vite 没起 / 端口没监听 / 代理后端没起 | 5.3、5.8 |
| 本机 `curl http://本机IP:3001` 200，对方不通 | 服务在跑但被防火墙挡 | 5.4 |

> 关键经验：**本机 `curl http://本机IP:3001` 返回 200 只能证明"服务在跑 + 监听 0.0.0.0"**，不能证明外部能访问。本机回环不走应用层防火墙，所以本机测永远是通的，必须从对方电脑测。

### 5.1 确认同一局域网

对方手机/电脑和你连同一个 WiFi。

### 5.2 IP 是否变了

Mac 重新连网后 IP 可能变，重新执行 `ipconfig getifaddr en0`，把新 IP 告诉对方。

### 5.3 前端是否绑 0.0.0.0

```bash
lsof -nP -iTCP:3001 -sTCP:LISTEN
# 必须显示 *:3001（不能是 127.0.0.1 或 [::1]）
# 若是 127.0.0.1 说明 vite.config.ts 没加 host: true，加上重启 npm run dev
```

### 5.4 防火墙（最常见原因：能 ping 通但端口不通）

**症状特征**：对方 `ping 172.20.10.6` 通，但 `curl http://172.20.10.6:3001` 超时 / `nc -vz 172.20.10.6 3001` Connection refused。

**原因**：macOS 应用层防火墙（ALF）默认放行 ICMP（ping 走网络层，ALF 不管），但拦截**非 Apple 签名应用**的入站 TCP 连接，node / java 都属于此类。

**方案 A：关闭防火墙（内网开发最简单）**

```bash
sudo /usr/libexec/ApplicationFirewall/socketfilterfw --setglobalstate off
```

**方案 B：保留防火墙，仅放行 node / java**

```bash
sudo /usr/libexec/ApplicationFirewall/socketfilterfw --add "$(which node)"
sudo /usr/libexec/ApplicationFirewall/socketfilterfw --unblockapp "$(which node)"
sudo /usr/libexec/ApplicationFirewall/socketfilterfw --add "$(which java)"
sudo /usr/libexec/ApplicationFirewall/socketfilterfw --unblockapp "$(which java)"
```

**查看状态**：

```bash
sudo /usr/libexec/ApplicationFirewall/socketfilterfw --getglobalstate
# State = 0  关闭（外部可直接访问）
# State = 1  开启（需要白名单放行 node/java）
```

### 5.5 路由器 AP 隔离

某些公共/酒店 WiFi 开启了「客户端隔离」，同网段设备互相访问不了。**症状**：ping 也不通。换个人热点或家用 WiFi。

### 5.6 校园/公司网跨 VLAN

对方网段不同，需要走 VPN 或用 Cloudflare Tunnel 内网穿透（见第六节）。

### 5.7 Vite allowedHosts 拦截（返回 403）

**症状**：对方浏览器返回 `Blocked request. This host ("xxx") is not allowed.`

**修复**：`vite.config.ts` 设 `server.allowedHosts: true`，重启 `npm run dev`。

### 5.8 服务实际没起 / 代理后端没起

```bash
# 本机自测，全 200 才算服务正常
curl -I http://localhost:3001/                                    # 前端
curl -I http://localhost:8081/wms-api/api/system/auth/captcha    # 后端
curl -I http://localhost:3001/wms-api/api/system/auth/captcha    # 通过前端代理后端
```

## 六、（可选）跨网段 / 外网访问：内网穿透

当局域网隔离或需要外网访问时，用 **Cloudflare Tunnel**（推荐，免费、无需公网 IP、无需端口映射）把本机端口暴露到公网。

### Cloudflare Tunnel（推荐，已配置）

```bash
# 安装（一次性）
brew install cloudflared

# 启动临时隧道，把前端 3001 暴露到公网
nohup cloudflared tunnel --url http://localhost:3001 > /tmp/cloudflared.log 2>&1 &

# 查看分配的公网域名
grep -oE "https://[a-z0-9-]+\.trycloudflare\.com" /tmp/cloudflared.log | head -1
# 输出类似: https://stocks-crest-lasting-episode.trycloudflare.com
```

详细配置、验证、固定域名、一键脚本见 **`docs/Cloudflare-Tunnel配置指南.md`**。

### 其他方案

- **ngrok**：`brew install ngrok` → `ngrok http 3001`，得 `https://xxxx.ngrok-free.app`，需注册拿 token。
- **frp**：需自有公网服务器跑 `frps`，本机跑 `frpc`，参考 https://github.com/fatedier/frp 。
