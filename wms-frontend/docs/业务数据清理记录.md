## 四、清理顺序说明

由于业务表之间**无物理外键约束**（仅逻辑关联），但按数据依赖关系采用以下顺序，确保数据一致性：

```
1. 单据明细（*_item）        ← 先删，主表还在时明细无法独立存在
2. 审核/状态日志（*_status_log）  ← 再删日志
3. 单据主表                   ← 再删主单
4. 库存流水（wms_inventory_log）← 先删流水
5. 当前库存（wms_inventory）   ← 最后清库存
```

所有操作在**一个事务**中执行（`START TRANSACTION ... COMMIT`），要么全部成功，要么全部回滚。

## 五、可复用清理脚本

脚本路径：`scripts/clean-business-data.sql`

### 5.1 执行前备份（强烈建议）

```bash
# 备份所有业务表
cd /tmp
mysqldump -uroot -p123456 wms_db_pro \
  wms_purchase_order wms_purchase_order_item wms_purchase_status_log \
  wms_stock_in wms_stock_in_item wms_stock_in_status_log \
  wms_stock_out wms_stock_out_item wms_stock_out_status_log \
  wms_transfer_order wms_transfer_order_item wms_transfer_status_log \
  wms_sale_order wms_sale_order_item wms_sale_status_log \
  wms_loss_order wms_loss_order_item wms_loss_status_log \
  wms_inventory wms_inventory_log \
  > wms_db_pro_business_backup_$(date +%Y%m%d_%H%M%S).sql
```

### 5.2 执行清理

```bash
cd ~/Documents/trae_projects/wms-frontend
mysql -uroot -p123456 wms_db_pro < scripts/clean-business-data.sql
```

脚本内置：
- **安全检查**：清理前校验 `sys_user`、`wms_warehouse`、`wms_goods_spu` 非空，任一为空则标记 STOP，需人工确认
- **事务包裹**：全部删除在一个事务内，失败自动回滚
- **清理后验证**：自动查询 20 张表的 `COUNT(*)`，应均为 0

### 5.3 恢复数据（如需回滚）

```bash
mysql -uroot -p123456 wms_db_pro < /tmp/wms_db_pro_business_backup_<时间戳>.sql
```
